# Marketing Skills Catalog Family Review - 2026-07-16

## Scope and verdict

This is human-readable review evidence for the 23 admitted skills sourced from
`coreyhaines31/marketingskills`. It is not an install manifest and does not
change the dispositions in [`skills.registry.yaml`](../../skills.registry.yaml),
the resolved pins in [`skills.lock.yaml`](../../skills.lock.yaml), generated
catalogs, profiles, or consumer roots.

The independent recommendations are:

- **Retain (6):** `competitors`, `copywriting`, `cro`, `onboarding`, `pricing`,
  and `programmatic-seo`.
- **Fork (14):** `ab-testing`, `ads`, `analytics`, `aso`, `emails`,
  `free-tools`, `launch`, `paywalls`, `popups`, `referrals`, `schema`,
  `seo-audit`, `signup`, and `social`.
- **Merge (1):** merge `copy-editing` into `copywriting`, then remove the
  duplicate active entry.
- **Remove (2):** `marketing-ideas` and `marketing-psychology`.

These are recommendations for a separately authorized, serialized integration
task. Nothing in this review proves manager materialization or promotes client
support.

## Deferred integration vocabulary

The exact common mechanics used in the rows below are:

- **Fork delta:** create a maintained top-level `<skill-id>/` fork based on
  upstream `v2.6.0` commit `2815104...`; change the registry source from
  `external-git`/`skills/<skill-id>` to `registry-local`/`<skill-id>`; remove
  the active URL, tag, and observed-commit pin fields; preserve MIT/Corey
  Haines attribution plus the base release, commit, and fork reason in the
  appropriate source/provenance notes; generate a digest-based lock and
  catalog through the normal generators. Codex, Claude, and OpenCode remain
  `planned`, and profiles remain unchanged pending separate manager proof.
- **Retain delta:** keep `active`, `external-git`, `v2.6.0`, commit
  `2815104...`, and existing attribution. Keep every client `planned` and make
  no profile change. Apply the row's description/notes change in the registry
  and seek the listed content correction in a reviewed upstream release; if a
  required pre-exposure correction cannot land upstream, review a local fork
  instead of patching an imported copy.
- **Remove delta:** remove the active registry and lock entries, regenerate
  catalogs, and remove or retarget admitted cross-links. There is no profile or
  real-consumer removal in the current baseline. Historical attribution stays
  in this evidence; no replacement is admitted automatically.
- **Merge delta:** remove `copy-editing` from the active registry and lock (or
  use a time-bounded non-installable legacy alias only if migration proves it
  necessary), fold the reviewed checklist into `copywriting`, retarget links,
  and regenerate catalogs. Keep the `copywriting` external pin only if the
  merge lands in a reviewed upstream release; otherwise make an attributed
  registry-local `copywriting` fork. Clients remain `planned`.
